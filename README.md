# CPRI PowerNext-AI Hackathon — End-to-End Pipeline & Deliverables

An automated, physics-grounded machine learning pipeline for electrical equipment test analysis, digital twin residual monitoring, and hot-spot temperature prediction.

---

## 1. Overview

During high-voltage testing of power equipment (e.g., transformers, switchgear, cable joints), CPRI records operating parameters (applied voltage, load current, ambient temperature, test duration) and thermal sensor readings (S1, S2, S3, S4). For 1,000 historical tests, calibrated hot-spot reference temperatures (`Reference_Parameter`) and engineer validity verdicts (`Validity_Label`) are known.

This repository provides an automated, reproducible, end-to-end pipeline that processes 350 unseen test records to:
1. Detect anomalous or corrupted tests (`Valid` vs. `Invalid`) using digital twin sensor residual modeling and empirical separation thresholds.
2. Predict internal hot-spot temperatures (`Predicted_Reference_Parameter`) using regularized polynomial regression trained strictly on verified `Valid` records.
3. Quantify test anomalies via a multi-component **Attention Score** and produce all required competition deliverables.

## 5. Attention Score Formula

The attention scoring mechanism identifies the tests most deserving of expert human review. Four independent components are computed and normalized to $[0.0, 1.0]$, combined with equal weighting (25% each):

$$\text{Attention Score} = 0.25 \cdot c_{\text{invalid}} + 0.25 \cdot c_{\text{residual}} + 0.25 \cdot c_{\text{missing}} + 0.25 \cdot c_{\text{temp\_percentile}}$$

### Component Definitions

1. **Invalidity Flag ($c_{\text{invalid}}$)**:
   $$c_{\text{invalid}} = \begin{cases} 1.0 & \text{if } \text{Validity\_Label} = \text{"Invalid"} \\ 0.0 & \text{if } \text{Validity\_Label} = \text{"Valid"} \end{cases}$$
   *Rationale*: Any flagged test represents a potential failure or bad recording that requires review.

2. **Sensor Residual Severity ($c_{\text{residual}}$)**:
   $$c_{\text{residual}} = \min\left(1.0, \frac{\max_{s \in \{S1, S2, S3\}} |y_s - \hat{y}_s|}{\theta}\right)$$
   where $\hat{y}_s$ is the digital twin prediction and $\theta$ is the empirical decision threshold ($\approx 2.0$). Missing readings are assigned $1.0$.
   *Rationale*: The larger the deviation between physical sensors and expected digital twin values, the more acute the anomaly.

3. **Missing-Measurement Count ($c_{\text{missing}}$)**:
   $$c_{\text{missing}} = \frac{\text{count}(\text{missing features in } [V, I, T_{\text{amb}}, t, S_1, S_2, S_3, S_4])}{8.0}$$
   *Rationale*: Telemetry dropouts compromise test fidelity.

4. **Temperature Percentile Rank ($c_{\text{temp\_percentile}}$)**:
   $$c_{\text{temp\_percentile}} = \frac{\text{rank}(\hat{T}_{\text{ref}}) - 1}{N - 1} \in [0.0, 1.0]$$
   *Rationale*: High-temperature tests represent maximum thermal and insulation stress on equipment; critical hot-spots warrant priority oversight.

## 6. Integration QA & Testing

Run the full automated test suite:

```bash
pytest tests/ -v
```

The suite is 90 tests. The two integration modules below are P4's;
`test_p1.py` covers the detector and `test_p3.py` the benchmark.

### `tests/test_submission.py` (Deliverables Compliance)
- Exact row count (350) and required columns (`Test_ID`, `Predicted_Reference_Parameter`, `Validity_Label`).
- Perfect alignment with `Sample_Submission` row order.
- No NaN, infinite, or non-finite values.
- Validity labels strictly restricted to `"Valid"` and `"Invalid"`.
- `summary.json` schema validation and exact numerical consistency with CSV.
- Programmatic word count limit enforcement ($\le 100$ words).
- Exact 3 attention IDs matching valid test records.
- Deterministic output consistency for identical measurement vectors.

### `tests/test_robustness.py` (Adversarial Attacks & Hidden Dataset QA)
Evaluates pipeline resilience against 6 deliberate corruption scenarios:
1. **Randomly NaN 10% of sensor readings**: Pipeline executes cleanly, detects missing telemetry, and outputs 350 valid rows.
2. **Drop `Sensor_S4` column entirely**: Irrelevant auxiliary sensor absence does not alter validity verdicts.
3. **Duplicate 20 random rows**: Duplicate measurement vectors are correctly identified and flagged `Invalid`.
4. **Multiply load current by 1.3x**: Predictions remain stable, finite, and within physical bounds under out-of-distribution stress.
5. **Insert all-zero sensor row**: Disconnected sensor telemetry is caught and flagged `Invalid`.
6. **Shuffle column order**: Column indexing ensures identical outputs regardless of feature column ordering.
